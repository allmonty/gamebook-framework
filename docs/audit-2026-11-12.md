## 1. Bugs & Technical Issues

### 1.1 (P1) Buttons show no keyboard focus — `site/css/site.css`
`.btn` uses `clip-path: var(--chamfer)`. A clip path also cuts off everything painted outside the shape, including the global `:focus-visible` outline (offset 2px outside) and the hover glow. So Attack, Take, Use, Restart, Begin and every call-to-action have no visible focus ring (WCAG 2.4.7). The "Open file" label has the same problem with its `focus-within` glow. `.gb-choice` is fine: it uses an inset shadow. **(verify in a browser)**

```css
/* A clip-path hides outlines, so the focus ring is drawn inside the button. */
.btn:focus-visible { outline: none; box-shadow: inset 0 0 0 3px var(--canvas); }
.btn-ghost:focus-visible,
.btn-danger:focus-visible,
.gb-actions label.btn:focus-within { outline: none; box-shadow: inset 0 0 0 2px var(--text); }
```
Remove the dead rule `.gb-actions label.btn:focus-within { box-shadow: var(--glow); }`. The `box-shadow` in `.btn:hover` is also clipped and does nothing; delete it and keep `filter: brightness(1.1)`.

### 1.2 (P1) The editor traps Tab; its comment describes code that does not exist — `site/lib/src/ui/lab_view.dart`
`_indent` swallows every Tab. The comment says "Escape-then-Tab still move focus", but nothing handles Escape. A keyboard user can only leave backwards with Shift+Tab (WCAG 2.1.2).

```dart
  bool _escaped = false;

  /// Tab inserts two spaces instead of leaving the editor. Shift+Tab, or
  /// Escape then Tab, still moves focus, so keyboard users are not trapped.
  void _indent(KeyboardEvent e, HTMLTextAreaElement area) {
    final leaving = _escaped;
    _escaped = e.key == 'Escape';
    if (e.key != 'Tab' || e.shiftKey || leaving) return;
    e.preventDefault();
    final start = area.selectionStart;
    area.setRangeText('  ', start, area.selectionEnd, 'end');
    area.dispatchEvent(Event('input'));
  }
```
(`_indent` stops being `static`.) Tell the user: add a hint under the textarea, linked with `aria-describedby`, from new strings `player.editHint` — en: "Tab indents. Press Esc, then Tab, to leave the editor." pt: "Tab recua o texto. Aperte Esc e depois Tab para sair do editor." Test in `site/test/browser/lab_view_test.dart`: Tab inserts two spaces; Escape then Tab is not prevented.

### 1.3 (P1) Twine import fails on any brace in the text, and on a title with `_` — `engines/dart/lib/twine.dart`
The imported text goes into `Story.fromJson`, whose template check throws on a stray `{` or `}`. Twine text is full of them (Chapbook inserts, JavaScript, CSS, Harlowe). The whole import then dies with "cannot import" instead of reporting. Also the story `id` comes from `_slug(title).toLowerCase()`, which keeps `_`, but a story id allows only `[a-z0-9-]`.

```dart
/// Twine text is literal: its braces are not placeholders.
String _literal(String s) => s.replaceAll('{', '{{').replaceAll('}', '}}');
```
Use it in `importTwine`:
```dart
      choices.add({'text': _literal(text), 'to': to});
    ...
    final node = <String, Object?>{'title': p.name, 'text': _literal(text)};
    ...
    'id': _slug(title).toLowerCase().replaceAll('_', '-'),
```
Keep the duplicate-choice check comparing the escaped text. Test in `twine_test.dart`: a passage with `<<set $x to {a: 1}>>` and a `StoryTitle` of `My_Story` imports, and plays the text back with single braces.

### 1.4 (P2) Undo does not bring the music back — `site/lib/src/play/play_session.dart`
The session tracks music from `MusicChanged` events, but `engine.undo()` returns only `NodeEntered`. After undoing past a page that changed the music, the wrong track keeps playing. The engine state already holds the truth, so delete the copy:

- remove the field `String? _music;`, the line `_music = null;` in `_begin`, and the `case MusicChanged` branch in `_record`;
- in `_view`: `audio: AudioCue(music: _engine.state.music, sounds: [...])`.

Test in `play_session_test.dart`: a story with `undo: 1`, page A with no music, page B with `music`; choose then undo; `view.audio.music` is null.

### 1.5 (P2) Editing a story leaves the old game's music playing — `lab_view.dart`, `player_view.dart`
`LabView._refresh` builds a new `PlayerView` (with a new `AudioOutput`) on every edit and drops the old one without stopping it. A playing audio element is not collected, so tracks pile up, and the page has no way to stop them.


```dart
    } else {
      final host = el('div');
      _playPane.replaceChildren(host);
      _player = PlayerView(host, game, m, mediaBase: mediaBase);
    }
```

### 1.7 (P2) Picking an option or rerolling throws keyboard focus away — `player_view.dart`, `creation_panel.dart`
`onChange: render` replaces the whole creation panel, so the button just pressed is destroyed and focus falls to `<body>`. A keyboard or screen-reader user starts from the top of the page after every pick.

```dart
// player_view.dart, in render(): onChange: _redrawKeepingFocus,
  void _redrawKeepingFocus() {
    final key = document.activeElement?.getAttribute('data-key');
    render();
    if (key != null) {
      (host.querySelector('[data-key="$key"]') as HTMLElement?)?.focus();
    }
  }
```
In `creation_panel.dart` add `attrs: {'data-key': 'reroll'}` to the reroll button and `'data-key': '${group.id}.${option.id}'` to each option (ids are `[A-Za-z0-9_-]`, safe in the selector).

### 1.10 (P1, hardening) Things a stranger's file can still do
`AGENTS.md`: "anything it can make the engine do must be bounded and checked when it is loaded." Four gaps:

**a. Conditions nest without limit** (`engines/dart/lib/condition.dart`). `{"not":{"not":{...}}}` thousands deep overflows the stack in `Condition.fromJson`, `evaluate` and `_unmet`. That is an `Error`, so `package.dart` and `EditSession` do not catch it. Needs D1.
```dart
  static const maxDepth = 32;

  factory Condition.fromJson(Object? json, String path, [int depth = 0]) {
    if (depth > maxDepth) {
      throw StoryFormatException(path, 'conditions nest deeper than $maxDepth');
    }
    Condition child(Object? json, String path) =>
        Condition.fromJson(json, path, depth + 1);
    // ...then use `child` for 'all', 'any' and 'not' instead of Condition.fromJson
```

**b. Media paths are not checked** (`engines/dart/lib/validate.dart`). `image`, `cover`, `music` and `sound` accept any string: `https://tracker.example/p.png`, `//host/x`, `../../x`. The site puts it straight into `img src` and `audio src` (`player_view.dart`, `audio.dart`), so a story pasted into the playground, or shipped in a `.gamebook`, can make the reader's browser call a third-party server. `readPackage` lets it through because missing media are allowed. `belongsInPackage` already knows the rule. Needs D2.
```dart
// validate.dart (import 'package.dart' show belongsInPackage;)
  void _asset(String where, String path, String what) {
    if (!path.contains('/') || !belongsInPackage(path)) {
      error(where, '$what must be a file under images/ or audio/: $path');
    } else if (assetExists != null && !assetExists!(path)) {
      error(where, '$what file not found: $path');
    }
  }
```
Replace `_image` and `_file` with it (`_image` keeps its null check).

**c. Integers are unbounded.** Stat values, `times`, `count`, `stack`, `upTo`, enemy `attack` and `health`, bonuses, `rules.undo`. On the Dart VM they wrap at 64 bits; compiled to JavaScript they are doubles and lose precision above 2^53. The same story can then play differently in two engines, which is what the conformance suite exists to prevent. Also `rules.undo: 1000000000` keeps that many states in memory. Fix in one place, `JsonObject.integer` in `json_reader.dart`. Needs D3.
```dart
  static const maxInt = 1000000; // big enough for any gamebook, exact everywhere

  int integer(String key) {
    final value = _typed<int>(key, 'an integer');
    if (value.abs() > maxInt) throw error(key, 'must be between -$maxInt and $maxInt');
    return value;
  }
```
Raw `is int` reads need the same check: `Operand.fromJson`, `Quantity.fromJson`, `ResultsRow._pair`, the two `bonus` maps.

**d. Packages** (`engines/dart/lib/package.dart`). No check of the compressed size at all: add `if (bytes.length > maxBytes) throw _tooBig(maxBytes);` as the first line of `readPackage` (no decision needed). Two known limits stay, both already half-noted by the `shortcut:` comment: an entry that lies about its size is inflated whole before the cap is seen, and `archive` 4.6.0 inflates entries flagged as Unix symlinks during `decodeBytes`, before any of this code's checks run. Extend the `shortcut:` comment to name the symlink case.

### 1.11 (P2) The site's build is not reproducible, and deploys without tests — `.gitignore`, `.github/workflows/pages.yml`

```gitignore
build/
.venv/

```
```yaml

      - run: dart test
      - run: dart run tool/build.dart
```
(Replace the plain `dart pub get` with the `--enforce-lockfile` one; use it in `ci.yml`'s site job too.)

## 2. Fact-Checking & Content Completion

### 2.1 (P1) The comparison is unfair to ChoiceScript, Ink and Twine — `site/strings/{en,pt}.json`, `spec/comparison.md`
These are public claims about other people's tools, on the home page.

- **ChoiceScript, "Checked before players see it: No".** Wrong. ChoiceScript ships Quicktest (walks every branch) and Randomtest (plays the game thousands of times at random), which is the same idea as `simulate_story`. **(verify, 3.1)**
- **ChoiceScript, "Variables only".** It also has `*rand` for dice.
- **Ink, "No: external functions".** Ink has variables, functions, lists and a built-in `RANDOM(min, max)`. Dice and stats need no external function; what is missing is a ready-made stats, inventory and combat model. `comparison.md` repeats this ("hand-built on top of external functions").
- **Ink, "Yes, with community runtimes".** The main runtime is inkle's own C#; inkjs and the Dart port are the community ones.
- **Twine, "Checked: No".** The Twine 2 editor marks broken links on the story map.
- **Ours, "Runs natively in apps: Yes: any language can parse it".** Parsing JSON is not running a game. One engine exists, in Dart, and it is not on pub.dev yet.

Replacement strings:

| Key | English | Portuguese |
|---|---|---|
| `home.compare.ink1` | Not built in: variables and RANDOM(), the rest by hand | Não embutido: variáveis e RANDOM(), o resto à mão |
| `home.compare.ink2` | Yes: official C# runtime, JavaScript and community ports | Sim: runtime oficial em C#, JavaScript e portes da comunidade |
| `home.compare.twine3` | Partly: the editor marks broken links | Em parte: o editor marca links quebrados |
| `home.compare.cs1` | Variables and *rand; no inventory or combat | Variáveis e *rand; sem inventário nem combate |
| `home.compare.cs3` | Yes: Quicktest and Randomtest | Sim: Quicktest e Randomtest |

| `home.t8.text` | Language-neutral test cases with scripted dice, so a second engine in any language can prove it plays every story exactly like the reference. | Casos de teste independentes de linguagem, com dados roteirizados, para que um segundo motor em qualquer linguagem prove que joga cada história exatamente como o de referência. |

### 2.2 (P1) The README describes a private app as if it were this repo — `README.md`
"Players can toggle music and sound effects in the app settings", "All unlocked entries are shown on the character screen", "not shown to players in release builds", "saves are kept if they're still compatible", "Bundled (official) games cannot be overwritten". None of that exists here: the website player has no settings, no saves and no package import, and its achievements last until the page reloads. A reader cannot tell the format from an app they cannot get. Insert under the heading "What you can do as a game writer":

The spec has the same habit in normative text ("The app does not list a story with drafts in release builds", B13; "Players can switch music ... in the settings", B6). Check whether the unread Part A or B1 defines "the app". If not, add to B1: "**The app** in this document means any player that shows a story to a reader. What it says the app does is what a player should do; it is not part of what makes a story valid."

## 4. Usability & UX/UI

### 4.1 (P1) Focus ring on buttons — see 1.1.

### 4.2 (P1) Music cannot be stopped — `audio.dart`, `player_view.dart`
A page's `music` loops forever with no control: WCAG 1.4.2, and spec B6 says players can switch sound off. No shipped example has audio today, so this bites the first author who adds some. Add a toggle to the player's controls, shown only when the story has any `music` or `sound`:

```dart
// audio.dart
  bool muted = false;

  void setMuted(bool value) {
    muted = value;
    _music?.muted = value;
  }
  // in play(): set `..muted = muted` on the new music element; skip sounds when muted.
```
```dart
// player_view.dart, in _controls(), when view.hasAudio:
        onClick(
          el('button', cls: 'btn btn-ghost', text: m('player.mute'),
              attrs: {'aria-pressed': '${_audio.muted}'}),
          () { _audio.setMuted(!_audio.muted); render(); },
        ),
```
`PageView.hasAudio` = any node of the story has `music` or `sound`. Strings `player.mute`: en "Mute", pt "Sem som".

### 4.3 (P2) The Play/Edit tabs claim to be ARIA tabs but are not — `lab_view.dart`, `site.css`
`role="tablist"`, `tab` and `tabpanel` are set, but there is no `aria-controls`, no `aria-labelledby`, no arrow keys, and both tabs are in the Tab order. A screen reader announces "tab 1 of 2" and then the promised keys do nothing. The smallest correct fix is to stop claiming the pattern: remove the three `role` attributes and use `aria-pressed` in place of `aria-selected`.

```dart
  void _show({required bool play}) {
    _playTab.setAttribute('aria-pressed', '$play');
    _editTab.setAttribute('aria-pressed', '${!play}');
    ...
```
```css
.gb-tab[aria-pressed='true'] { color: var(--cyan); border-bottom-color: var(--cyan); text-shadow: var(--glow); }
```

### 4.4 (P2) A dice choice looks like any other, except for its colour — `views.dart`, `play_session.dart`, `player_view.dart`
A check or table differs only by an amber border (WCAG 1.4.1). Spec B10 says the UI should show what will be rolled before the tap; the tutorial tells authors to type it into the choice text by hand. Show it from the data: add `String? roll` to `ChoiceItem` (for a check: roll, `add` label, operator, target, for example "2d6 + Skill ≥ 16"; for a table: its roll) and draw it as a third line in the button, like the locked reason:

```dart
        if (c.roll != null) el('span', cls: 'gb-needs label', text: m('player.rolls', {'roll': c.roll!})),
```
Strings `player.rolls`: en "Roll {roll}", pt "Rolar {roll}".

### 4.5 (P2) The reason on a locked choice is the hardest text to read — `site.css`
`.gb-choice.locked { opacity: 0.55 }` also dims "Needs: Rusty key", the one line the reader must read, to roughly 3.7:1 at 11px (hand-computed). Dim the parts, not the whole:

```css
.gb-choice.locked { cursor: not-allowed; background: var(--surface); }
.gb-choice.locked .gb-text { opacity: 0.55; }
```

### 4.6 (P2) Text too small, one colour too dim — `site.css`
`.label` is 11px, and 10px in the stat pills, brand and phone bar. The log, which carries every dice result, is 11px uppercase. `--inert` (#64748b) on the canvas is about 4.05:1 (hand-computed), under the 4.5:1 that small text needs; it colours the chapter numbers and locked indexes.

```css
:root { --inert: #7f8ea3; }
.label { font-size: 12px; }
.gb-pill .label, .brand-text .label, .phone-bar { font-size: 11px; }
.gb-log li { font-size: 13px; text-transform: none; letter-spacing: 0; }
```

### 4.7 (P2) The sticky header on a phone — `site.css`
Brand plus five links wrap to two or three rows on a narrow screen, and stay stuck, taking a large share of the viewport. After each action the player moves focus to `.gb-page`, which can land under the header (WCAG 2.4.11).

```css
html { scroll-padding-top: 96px; }
@media (max-width: 640px) { .site-header { position: static; } }
```

### 4.8 (P2) What a screen reader hears after an action — `player_view.dart`, `log_panel.dart`
Three mechanisms compete: focus moves to the page article, the article is `aria-live`, and the log is `aria-live`. Both live regions are new elements on every render, and a region inserted with its text already in it is usually not announced. Result: dice rolls and wounds may never be spoken. Fix: remove `aria-live` from the article and from `logPanel`; give `PlayerView` one status element that it creates once, keeps outside the re-rendered subtree, and fills after each render with the log lines joined by ". ":

```dart
  late final _status = el('p', cls: 'gb-sr', attrs: {'role': 'status'});
  // render(): host.replaceChildren(_status, el('div', children: [...]));
  //           _status.textContent = view.log.map((l) => logText(l, m)).join('. ');
```
```css
.gb-sr { position: absolute; width: 1px; height: 1px; overflow: hidden; clip-path: inset(50%); }
```
In the same file family: `creation_panel.dart` renders "[x]" and "[ ]" as text next to `aria-pressed`, so it is read twice; add `'aria-hidden': 'true'` to that span. When a pick group is full, further clicks are ignored with no sign; set `aria-disabled="true"` and the `locked` class on the unpicked options.

### 4.9 (P2) Fonts come from Google on every page — `templates/layout.html`
Three families load from `fonts.googleapis.com`: a third-party request before first paint, the visitor's IP address sent to Google (3.11), and a site that looks different offline. Self-host: put the woff2 files in `site/assets/fonts/`, declare them with `@font-face` and `font-display: swap` in `site.css`, and delete the three `<link>` lines. Cheaper still: drop one family (Space Grotesk and Plus Jakarta Sans do nearly the same job here).

### 4.10 (P3) Sharing and search — `templates/layout.html`, `site_builder.dart`
No canonical link, no `hreflang` alternates between `/en/` and `/pt/`, no Open Graph tags (a shared link shows a bare URL). The language switch reads "PT" or "EN" with no name. Add a builder value `site.url` (`https://allmonty.github.io/gamebook-framework/`) and:

```html
<link rel="canonical" href="{{site.url}}{{lang}}/{{path}}">
<link rel="alternate" hreflang="{{lang}}" href="{{site.url}}{{lang}}/{{path}}">
<link rel="alternate" hreflang="{{otherLang}}" href="{{site.url}}{{otherLang}}/{{path}}">
<meta property="og:title" content="{{page.title}}">
<meta property="og:description" content="{{page.description}}">
<meta property="og:image" content="{{site.url}}assets/logo.jpeg">
```
```html
<a class="lang-switch label" href="..." hreflang="{{otherLang}}" lang="{{otherLang}}" aria-label="{{nav.otherLanguage.name}}">{{nav.otherLanguage}}</a>
```
New string `nav.otherLanguage.name`: in `en.json` "Português", in `pt.json` "English". The CSS styles `.site-nav a[aria-current='page']` but the layout never sets it; set it in `_writePage` for the Tutorial and Playground links.

### 4.11 (P3) Home page details — `templates/index.html`
- Feature cards are labelled "B6 // B10", "B5", "B13 // B14": spec section numbers, noise to a visitor. Make each a link to that section of the spec, or remove them.
- `<div class="phone" aria-label="...">` has no role, so the label is ignored. Add `role="group"`.
- The comparison table's corner is an empty `<th scope="col"></th>`. Make it `<td></td>`.
- With JavaScript off, every example is an empty box. Put a fallback line inside `exampleEmbed` (`embed.dart`), which the player replaces: `<noscript><p>{{player.noscript}}</p></noscript>`; en "Turn on JavaScript to play this example.", pt "Ative o JavaScript para jogar este exemplo."

### 4.12 (P3) Player details
- **Restart** sits beside **Undo**, same size and style, and wipes the game in one click (`player_view.dart` `_controls`). Make it two-step: first click changes the label to `player.restartConfirm` (en "Really restart?", pt "Recomeçar mesmo?"), second click restarts; any other action resets it.
- The current enemy and a low stat are marked by colour alone (`.gb-enemy.current`, `.gb-pill.low`). Add a "▶ " before the current enemy's name in `combat_panel.dart`.
- Text inputs and the editor use `outline: none` with only a border colour change, which disappears in Windows high-contrast mode. Use `outline: 2px solid transparent` instead of `none` in `.gb-field input:focus` and `.gb-edit textarea:focus`.
- The playground cannot open a `.gamebook`, though `readPackage` is pure Dart and would run in the browser, with the package's own images and sounds. This is a feature, not a fix: owner decision D5.
